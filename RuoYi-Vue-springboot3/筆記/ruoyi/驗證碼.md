## 一、攻擊者常見手法（為什麼需要驗證碼）

1. **身份欺騙 + 腳本反覆操作**
    - 在客戶端撰寫腳本，模擬瀏覽器行為，不斷：
        - 自動登入網站或論壇
        - 自動發帖、留言、送出表單
    - 從伺服器角度看，這些請求表面上跟正常使用者很像，但頻率異常高。
2. **偽造表單 + 直接 HTTP POST**
    - 攻擊者自行建立一個「跟你的註冊表單 / 發帖表單欄位完全相同」的窗體或程式。
    - 再透過程式直接對你的伺服器發送大量 `HTTP POST` 請求：
        - 自動註冊大量帳號
        - 自動提交垃圾內容（灌水、廣告）
3. **這類攻擊若未有效驗證與拒絕，後果**
    - 大量消耗系統資源（CPU、記憶體、資料庫連線）
    - 降低網站效能甚至導致程式崩潰
    - 造成資料庫充斥垃圾數據

## 二、驗證碼（字符校驗）的基本概念

**核心目的**：區分「人」與「程式」。

典型流程：

1. 伺服器隨機產生一串字元（數字 / 字母 / 符號）。
2. 把這串內容畫成一張圖片：
    - 加入干擾線、噪點、扭曲等，讓機器難以辨識（對抗 OCR）。
3. 使用者「用肉眼」讀圖上的字元，輸入到表單中。
4. 伺服器收到表單後，比對：
    - 使用者輸入的驗證碼
    - 與伺服器端事先儲存的正確值（通常有**有效時間**限制）
5. 驗證通過後，才允許進行「註冊 / 登入 / 發帖」等敏感操作。

由於人眼辨識圖片相對容易，而程式要正確識別則成本較高，因此能有效提高自動化攻擊難度。

## 三、驗證碼的主要作用

### 1. 防止批量自動註冊

- 阻擋「機器人大量開帳號」：
    - 減少垃圾帳號
    - 降低後續垃圾內容、詐騙帳號的風險
- 典型場景：
    - 各大論壇、社群網站的註冊頁面
    - 使用者 ID 註冊區

### 2. 防止暴力破解登入（暴力嘗試密碼）

- 對於**特定帳號**，攻擊者可能用程式反覆嘗試：
    - 不同密碼組合暴力破解
- 驗證碼可以：
    - 迫使攻擊者每次嘗試都必須先通過「圖片辨識」這道關卡
    - 大幅降低暴力登入的可行性與速度
- 常見於：
    - 網銀登入頁面（如招商銀行）
    - QQ 社區、論壇等需要帳號密碼登入的服務

> *** ⚠️註：驗證碼只是「抬高攻擊成本」，實務上仍需搭配登入次數限制、IP 限流等機制。***

### 3. 防止灌水與大規模匿名操作

- 未登入時發表言論（如匿名回覆、留言）很容易被用來：
    - 大量張貼廣告
    - 刷屏、惡意留言
- 驗證碼可以減少機器人：
    - 大量匿名回帖
    - 自動灌水、洗版
- 典型例子：
    - 百度貼吧未登入狀態下發帖需要輸入驗證碼

## 四、常見驗證碼形式（類型概觀）

> 註：下面的圖片格式只是各網站的實作差異，本質上都是「圖片 + 隨機字串 + 干擾」。
>
1. **簡單四位數字**
    - 隨機產生 4 位數字，顯示在圖片中。
    - 安全性低，機器容易破解，幾乎已不符合現代安全需求。
2. **隨機數字圖片（GIF 或一般圖片）**
    - 像 CSDN 登入使用：
        - 隨機數字
        - 字型、背景中規中矩，略有干擾
    - 安全性一般，阻擋簡單機器人尚可。
3. **數字 + 大寫字母（PNG 等）**
    - 例如 QQ 網站登入：
        - 隨機數字 + 大寫英文字母
        - 每次刷新字元位置、顏色不同
    - 比純數字更難猜，也較難被簡單 OCR 辨認。
4. **數字 + 字母 + 干擾像素 / 扭曲（BMP 等）**
    - 如早期 Hotmail 註冊：
        - 數字 + 大寫英文字母
        - 隨機干擾像素、隨機位置
    - 提高機器辨識難度。
5. **隨機英文 + 顏色 / 長度 / 位置變化（JPG 等）**
    - 如 Gmail 註冊：
        - 英文字母
        - 隨機顏色、隨機位置、隨機長度
    - 圖形特徵較複雜，增加對 OCR 的干擾。

> 不同網站選用 BMP / PNG / GIF / JPG 等格式，實務差異不在於「格式本身」，
>
>
> 而在於字型扭曲程度、干擾線、顏色、隨機性等設計。
>

## 五、使用驗證碼之外的安全提醒

1. **驗證碼不是萬能防線**
    - 它主要是針對「自動化腳本」與「暴力嘗試」加一道關卡；
    - 真正安全還需要：
        - 強密碼策略
        - 登入錯誤次數限制
        - IP 限流、登入頻率限制
        - 多因素認證（MFA）等。
2. **使用者自身密碼習慣非常關鍵**
    - 避免：
        - 1234、password、與帳號相同
        - 生日、手機號、身分證等容易猜測的資訊
    - 建議：
        - 至少 6 位以上（實務上建議 8–12 位以上）
        - 同時包含數字、大小寫字母、符號
